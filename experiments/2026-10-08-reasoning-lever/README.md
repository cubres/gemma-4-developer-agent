## Update, 14:40 UTC: the bench canary found its own bug

Bench version 17 (one arm, the direct-route candidate with thinking on) had the model ready 499 s after the first cell, faster than estimated, but every request was refused by vLLM with HTTP 400 because the canary's hand-built server command lacked `--reasoning-config`, which the organisers' launcher adds automatically whenever the Gemma 4 reasoning parser is used. The official scorer is therefore unaffected; the public reasoning payloads scoring 0.15-0.18 are consistent with that. [BENCH_V17_RESULT.md](BENCH_V17_RESULT.md) has the measured phase timings. Version 18, with the organisers' default flag, the scorer's compaction constants and the runtime environment moved out of the output folder, is running. [PLAN_2026-10-09.md](PLAN_2026-10-09.md) is the decision tree for tomorrow's single submission.

## Update, 15:15 UTC: the thinking-on route works on the real stack

Bench version 18, with the organisers' `--reasoning-config`, the scorer's compaction constants and the runtime moved out of the output folder, had the model ready at about 500 s and ran the one-task arm with reasoning on: 15 of 15 requests carried the 4,096-token thinking budget with no refusals, 13 well-formed tool calls, compaction firing as designed, median model call 7.2 s (p90 45 s). The arm still held because the agent produced no edit inside its 5.5-minute budget: it read whole files, spent two minutes writing a reproduction script to a path the harness forbids, and one compaction summary took a minute. That is agent behaviour, not plumbing. [BENCH_V18_RESULT.md](BENCH_V18_RESULT.md) has the gate table; the next direct-route candidate raises the time budget to eight minutes and tightens the prompt against that pattern.
