# Gemma 4 developer agent: campaign journal

This folder holds sanitized snapshots of the working documents behind the Gemma 4 Developer Agent campaign: a frontier sweep, a strategy synthesis, a state report and a set of engineering lessons. The snapshot is as of 2026-10-10. Official-row data is as of 2026-10-10 11:27 UTC, the timestamp of the last dated line in the campaign ledger. The coordinator for this campaign was an AI coding agent working under the owner's direction.

## Files

- [2026-10-08-frontier-sweep.md](2026-10-08-frontier-sweep.md): the public frontier on 8 October, what the sweep verified, refuted or corrected, and the plan's verdicts on its levers.
- [2026-10-09-strategy.md](2026-10-09-strategy.md): levers kept, refuted and repaired, the envelope arithmetic, the predeclared readings and the execution order as the sources state it.
- [2026-10-10-state.md](2026-10-10-state.md): the eight official rows to date with raw status and public score, the daily limit and pending-submission rule, what was running and what is next.
- [lessons.md](lessons.md): engineering lessons, each with the situation, the rule adopted, the evidence and how it was checked.

## Labels

- [V] checked against source, metadata, a server record, a log or a receipt.
- [P] another author's claim: a forum post, a host statement or a third-party write-up.
- [I] the author's inference.
- [V-inherited] checked in an earlier read of the same source, not re-read for this journal. Used in the frontier sweep and the state report only.

## Conventions

Scores are as the sources recorded them. A displayed score k/58 is truncated, so 0.08 is 5 tasks and 0.12 is 7 tasks. One public task is 0.0172.

Sources are summarised, not copied. Private worker identities, local paths, credentials and internal session identifiers are removed. Public notebooks are named by their slug. Forum posts are cited by topic number and paraphrased, and they are not attributed to named people; where a statement came from the competition host, the file says so.
